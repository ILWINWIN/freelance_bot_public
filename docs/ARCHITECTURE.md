# Архитектура Freelance Bot

`freelance_bot.app.Application` связывает настройки, хранилище, Telegram-интеграции и desktop-интерфейс. Точка запуска находится в `freelance_bot/__main__.py`.

| Компонент | Назначение |
| --- | --- |
| `telegram_bot/` | Long polling Bot API, маршрутизация команд и формирование карточек заказов. |
| `telegram_user/` | Адаптер Telethon, нормализация сообщений, история и очереди realtime и history. |
| `core/` | Импорт источников, фильтрация, классификация, дедупликация, архив и отложенное удаление заказов. |
| `storage/` | SQLite-репозиторий и JSON-профиль для черновиков откликов. |
| `ui/` | PySide6-интерфейс, лента, журнал и настройки. `core/desktop_service.py` связывает UI с прикладными операциями. |
| `sources/`, `scheduler/` | Контракт и реестр источников, очередь задач на отправку и восстановление её состояния. |
| `accounts/`, `security/`, `ai/`, `browser_automation/` | Учётные записи, хранение секретов, подготовка черновиков и управление браузерными сессиями. |

## Обработка Telegram

Bot API сохраняет входящие обновления в `telegram_inbox` перед продвижением общего offset. User API преобразует сообщения Telethon в `TelegramMessageEnvelope` и подаёт их в очереди realtime или history. Оба потока передают сообщения в `OrderService`, где применяются правила фильтрации, сверяются идентификаторы и отпечатки содержимого, а результаты записываются в SQLite. Desktop-лента читает сохранённые заказы. Журнал `telegram_order_deliveries` позволяет отслеживать отправку карточек и избегать повторов.

Bot API видит публикации, которые Telegram доставляет боту. User API получает доступные авторизованной сессии источники. Telegram API Hash и строка сессии User API защищаются через Windows DPAPI.

## Схема SQLite

[Database](../freelance_bot/storage/database.py) создаёт схему и применяет совместимые изменения колонок при открытии базы. Там определены таблицы заказов, источников, контрольных точек, входящих обновлений, псевдонимов сообщений, доставок, черновиков, задач и журнала. Архив хранится в состоянии заказа. Очередь отложенного удаления и записи об удалённых заказах защищают от повторного импорта.
